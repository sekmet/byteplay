# BytePlay decisions

1. Keep existing Go, anacrolix and /api/v1 legacy contracts; no rewrite or extra architecture.
2. Local-first, with explicit authorization for network-wide binding.
3. Use an ephemeral loopback internal header instead of embedding user Basic Auth in media process arguments.
4. Create fresh immutable HTTP transports; do not claim SOCKS5 proves anonymity or total peer/tracker isolation.
5. Use npm with existing package-lock.json, not the contradictory pnpm packageManager entry.
6. Work on isolated branch; no merge before required tests and media certification.

7. Runner policy updated by owner (2026-10-29): use GitHub-hosted `ubuntu-latest` for these quality checks now; consider self-hosted runners later if needed. This supersedes the earlier self-hosted-only constraint for current checks.

8. M6 playback seeks serialize cancel+Wait before publishing a new generation. Superseded generation files are removed after the old worker drains; they must never be served as the new generation. Keep pause intent from explicit client events, not playlist request frequency; the adapter lives outside Video.js internals. Effective copy-keyframe seek accuracy remains an explicit unverified acceptance gate.

9. M7 keeps the existing settings/proxy/indexer DOM hidden behind the new branded shell until UI parity is verified. New UI is vanilla JS + existing Tailwind and Video.js 8.24.0. Browser smoke metadata/status may be mocked only for deterministic layout checks; real seeded media tests remain separate and required. No new production JS runtime dependency.

10. M8 browser H264/AAC decoding proof uses installed Google Chrome because Playwright's stripped Chromium headless shell did not support AVC via MediaSource, even though Video.js 8.24.0/VHS was bundled. Keep responsive UI smoke on Chromium; require actual decoded frames and playback progression for media acceptance. Do not confuse missing test-browser codecs with a torrent or FFmpeg regression.
11. Docker must rebuild Tailwind from package-lock.json in a separate Node stage, retain a small Go/FFmpeg runtime, and fail CI unless explicit Basic Auth and media encoders work. Do not advertise an unpublished GHCR tag.

12. M8 resource accounting reserves HLS FFmpeg output up to the bounded per-playback cap under a dedicated mutex; count already generated bytes inside (not in addition to) their reservation. Torrent peers remain independently downloading; do not claim a hard global disk guarantee. Startup orphan recovery runs only before admission, requires a single-writer HLS root, ignores unowned paths and refuses a symlinked cache root. A SIGKILL/container restart fixture is an acceptance gate.

13. M8 local cache ownership is mandatory before startup recovery; the POSIX advisory file lock is held for the full server lifetime, tested with a competing Docker container, and released after SIGKILL. Unsupported host OSes fail closed. Do not imply NFS/distributed lock certification.
14. M8 torrent write checks wrap anacrolix's file storage and share the mutex/accounting ledger with HLS jobs. The backend's default mmap implementation truncates the **entire** file length before writing its first byte; quota checks must conservatively reserve that full length, never only the chunk size. This protects BytePlay-owned apparent file sizes but restricts files larger than the configured budget and is not an OS physical disk quota. Do not declare performance or full release certified.

15. Played history is opt-in by playback action, **stored locally per origin** as bounded and validated `localStorage` records; never persist HLS URLs/session tickets or backend credentials. Persist magnet source/selected file/time only after actual browser media `playing`, use textContent for titles, provide clear/remove. Reopening must go through authenticated torrent add and a fresh HLS generation; resume uses absolute seek rather than Video.js private APIs. For sensitive magnet tracker tokens, explain browser-local persistence. Settings controls receive explicit contrast pairs independent of legacy Tailwind theme variables.

16. The `anacrolix/torrent` file backend is selected once during package initialization. The Docker runtime sets `TORRENT_STORAGE_DEFAULT_FILE_IO=classic` to grow `.part` files by actual written extents; local operators must opt in before startup. Guarded torrent storage projects partial growth in classic mode, whole declared file length in default mmap mode; both share the HLS reservation mutex. Separate race-enabled classic tests and real Chrome HLS decoding are acceptance gates. This remains an apparent-size quota, not filesystem block allocation or a physical free-space guarantee.
